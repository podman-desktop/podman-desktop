Podman Desktop 1.31 Release

November 18, 2026 · 21 min read

Principal Software Engineer

Podman Desktop 1.31 Release

Podman Desktop 1.31 is now available. Click here to download it!

The new version of Podman Desktop is here with upgrades that speed up and secure your daily container workflow—featuring customizable bundled extensions, one-click image updates, a guided Windows Hyper-V setup, and important security patches:

  • Extension management: Override bundled extensions with installed replacements, update bundled extensions directly from the catalog, and configure auto-updates per extension — complete with "Update available" links and accurate lifecycle status indicators.
  • Container image updates: Update a single image or a bulk selection at once, with live progress tracking and cancellation in the task manager.
  • Guided Hyper-V setup on Windows: Configure Hyper-V for Podman from Settings > Resources without running Podman Desktop as an administrator.
  • Using existing volumes in Run Image page: Attach pre-created volumes directly from the Run Image page when launching a container.
  • Manage macOS settings with MDM: Administrators can now distribute default settings and enforce locked configurations across managed macOS devices using MDM preference plists.

Release details​

Extension management​

Previously, bundled extensions such as Podman, Docker, Kind, and Compose could not be updated between Podman Desktop releases—running a patched or newer version required sideloading it without any guarantee it would take precedence. Now, an installed extension can declare that it overrides a bundled extension, and the loader automatically gives it priority. You can also update bundled extensions directly from the catalog, with a new Overrides badge on the extension card confirming that your version is the one running.

Overriding bundled extensions is paired with granular control over automatic updates. You can now disable auto-updates for individual extensions from their details page. Whenever a newer version is waiting, an Update available link appears next to the version on both the extension card and the details page so you can apply the update manually. Lifecycle status indicators have also been refreshed across the UI to align with the updated look and placement of these controls on both extension cards and details pages

Container image updates​

Updating an image to a newer remote build no longer requires walking through the manual Pull Image flow and re-entering the tag—you can now check for and pull image updates directly from the UI.

Single image update: Trigger an update action directly from the upper-right corner of the Image Details page; Podman Desktop checks the local digest against the remote manifest and pulls the newer version only if an update exists. Bulk images update: Select multiple images from the Images list and run the update action across the entire batch at once, automatically skipping any images that are already up to date. Non-blocking task tracking: Image update checks and pulls run in the background as cancellable tasks in the task manager, ensuring large downloads never lock up the UI.

Guided Hyper-V setup on Windows​

On Windows systems with Podman 6.0.0 or later, Podman Desktop now checks podman system hyperv-prep --status to verify whether your account belongs to the Hyper-V Administrators group. When preparation has not yet been applied, a Podman: Prepare Hyper-V action appears on the Podman provider card in Settings > Resources. Triggering it requests a one-time administrator confirmation (UAC) to run podman system hyperv-prep in the background, hides the action once complete, and reminds you to sign out or restart Windows for the changes to take effect. Once preparation is complete, you no longer need to run Podman Desktop as an administrator to create a Hyper-V VM.

Using existing volumes in Run Image page​

Previously, configuring volume mounts on the Run Image page was restricted to host path binds, with no direct way to select a pre-created named volume without manually typing or remembering its path string. Podman Desktop 1.31 adds a flexible source-type selector to each mount row, making it easier to attach persistent storage.

Source-type selection: Each mount row now includes a dropdown allowing you to switch between Host path and Existing volume.

Engine-filtered volume dropdown: When Existing volume is selected, the host path input swaps for a dropdown populated from your available volumes, automatically filtered to match the target image's engine and sorted by name. The dropdown displays reader-friendly short names while submitting the full identifier as the bind source, making it effortless to select pre-created data volumes without copying and pasting long strings.

Manage macOS settings with MDM​

Podman Desktop now supports macOS Mobile Device Management (MDM) by reading managed preference files (.plist, in either XML or binary format) at startup and merging them with existing JSON configurations.

Administrators can deploy device-wide defaults and enforce restrictions using a locked array at /Library/Managed Preferences/io.podman_desktop.PodmanDesktop.plist, or supply account-specific startup overrides via per-user plists at /Library/Managed Preferences/<username>/io.podman_desktop.PodmanDesktop.plist. By combining the roles of default-settings.json and locked.json into standard macOS managed preference files, IT teams can natively standardize and lock Podman Desktop settings across their macOS fleets.

Security hardening​

This release includes fixes for multiple security vulnerabilities reported through Dependabot. Updated direct and transitive dependencies address known CVEs and help keep Podman Desktop's container and extension workflows secure.

Other improvements​

  • Catalog filters: The extension catalog now understands is:featured and not:featured in its search, so you can narrow results to featured extensions (#19616).
  • Catalog search placement: Search moved below the tabs, and the Install Custom dialog now closes as soon as the installation starts (#19889, #19621).
  • Settings navigation: SettingsNavItem supports key shortcuts, and preferences search matches both the setting key and its display name (#19204).
  • Registries settings: The registries page now exposes labeled regions for screen reader users (#19679).
  • Task toast notifications: Enabled by default, so long-running work reports back when it finishes (#19845).
